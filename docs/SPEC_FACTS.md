## EIP-8141 Frame Transaction (draft, created 2026-01-29) [eips.ethereum.org/EIPS/eip-8141]
- S, checked: type 0x06. Payload: chain_id, nonce, sender, frames, signatures, fees, blob_versioned_hashes. MAX_FRAMES = 64. FRAME_TX_INTRINSIC_COST = 12000. FRAME_TX_PER_FRAME_COST = 475. ENTRY_POINT = 0xaa. (EIP-8250 replaces `nonce` with `nonce_keys, nonce_seq`; see below.)
- S, checked: frame = [mode, flags, target, limits, value, data]; limits = [execution, state]. Flags bits 0-1 approval scope, bit 2 atomic batch.
- S, checked: modes: 0 DEFAULT (runs as entry point), 1 VERIFY (STATICCALL; only APPROVE changes approval), 2 SENDER (runs as tx.sender; needs approval).
- S, checked: APPROVE opcode 0xaa, scopes: 0 none, 1 payment (sets payer, increments nonce, collects max_cost), 2 execution, 3 both.
- S, checked: signature entry [scheme, signer, msg, signature]. Schemes: ARBITRARY 0x0 (100 gas, bytes checked in EVM, readable via SIGDATACOPY; `signer` must be empty), SECP256K1 0x1 (2800 gas), P256 0x2 (6700 gas). msg is empty (signs compute_sig_hash) or an explicit 32-byte digest; all-zero digest invalid.
- S, checked: opcodes TXPARAM 0xb0, FRAMEDATALOAD 0xb1, FRAMEDATACOPY 0xb2, FRAMEPARAM 0xb3, SIGPARAM 0xb4, SIGDATACOPY 0xb5. TXPARAM(0x08) returns compute_sig_hash(tx). SIGPARAM(0x03, i) returns the ARBITRARY byte length.
- U: "eip8141.io notes SIGDATACOPY's value collides with EIP-8272." eip8141.io was blocked; EIP-8272 (Recent Roots, created 2026-05-15) text does not show 0xb5 in a quick search. Unverified.
- S, checked: a VERIFY frame that reverts or halts makes the transaction invalid. After all frames run, payer must be set.
- S, checked: expiry verifier: a VERIFY frame to EXPIRY_VERIFIER (0x81413f0cF12e9b6a49B1D0439E081c577D57FfFf) fails unless block.timestamp <= 8-byte expiry.
- S, checked and **corrected**: STANDARD_TOKEN_COST = 4 gas per token; tokens = zero bytes + 4 x non-zero bytes, so 4 gas per zero byte and 16 gas per non-zero byte. Bytes of an ARBITRARY entry with empty `msg` are priced as if all non-zero (16 gas per byte). There is also a floor: TOTAL_COST_FLOOR_PER_TOKEN = 16 gas per token with 4 tokens per byte = **64 gas per byte**, applied when the floor exceeds the standard total. So "16 gas per byte" is not an upper bound; the BRIEF table's calldata column must be recomputed by script with both terms.
- S, checked: the security considerations are now read. Relevant points: deploy frames can be front-run (wallets should resubmit without the deploy frame); ARBITRARY signatures with empty `msg` are malleable unless the verifier accepts exactly one encoding; an approval based on an explicit `msg` or any check that does not commit to all frames authorises an open-ended list of frames; a payer's charge is bounded by `max_fee`.
- S (was I, Q1): public-mempool rule 6: "The sum of `limits.execution` values across the validation prefix, plus the intrinsic cost of validating `tx.signatures`, must not exceed MAX_VERIFY_GAS." The signature verification cost is 100 per ARBITRARY entry; the cost of the signature bytes is a separate intrinsic term (`signature_data_cost`). I read this as: signature bytes do not count toward the cap, but the *declared* execution limits of every validation-prefix frame (including a deploy frame) do. Confirm on a devnet.
- S (was I, Q2): compute_sig_hash covers the whole transaction, fee fields and all frames included. Only the raw bytes of empty-`msg` signatures are elided (their length is kept). An explicit digest is allowed by the protocol but the Security Considerations warn against approving execution on it.

## Public mempool rules in the draft
- S, checked: MAX_VERIFY_GAS = 100,000; MAX_VERIFY_STATE_GAS = 500,000.
- S, checked: recognised prefixes: self_verify; deploy + self_verify; only_verify + pay; deploy + only_verify + pay. An expiry_verify frame may come first and is skipped for shape matching.
- S, checked: SLOAD only on tx.sender storage. Banned in validation: GASPRICE, BLOCKHASH, COINBASE, TIMESTAMP (except canonical expiry verifier), NUMBER, PREVRANDAO, GASLIMIT, BASEFEE, GAS (except before a call), BALANCE, SELFBALANCE, SSTORE and CREATE/CREATE2/SETDELEGATE (except in first deploy frame), SELFDESTRUCT, others.
- S, checked: non-canonical paymaster: one pending tx (MAX_PENDING_TXS_USING_NON_CANONICAL_PAYMASTER = 1). Replacement needs 10% fee bump. One pending frame transaction per sender in the public mempool.

## EIP-8250 keyed nonces (draft, created 2026-04-16) [eips.ethereum.org/EIPS/eip-8250]
- S, checked and **corrected**: the EIP-8141 `nonce` field is replaced by `nonce_keys` (a list of up to MAX_NONCE_KEYS = 16 uint256 keys, strictly increasing) and `nonce_seq` (uint64). `nonce_keys == []` selects the legacy account nonce. (The earlier note "(nonce_key, nonce_seq), key 0 aliases the legacy nonce" described an older draft.)
- S, checked: keyed sequences live in storage of NONCE_MANAGER = 0x8250968C12e01A19d6F667b9B2F3b3A4d0e51cB7 at slot keccak256(pad32(sender) || uint256(key)). An absent slot reads 0. Only the protocol writes these slots.
- S, checked, new: `nonce_seq == MAX_NONCE_SEQ` with a non-empty key set marks every selected key single-use: consumption writes MAX_NONCE_SEQ, so the key can never be selected again.
- S, checked and **corrected**: KEYED_NONCE_FIRST_USE_GAS = 20000 is no longer in the text. First use now costs state gas KEYED_NONCE_FIRST_USE_STATE_GAS = STATE_BYTES_PER_STORAGE_SET x CPSB, plus KEYED_NONCE_ACCESS_COST = COLD_STORAGE_ACCESS + STORAGE_WRITE per key.
- S, checked: consumption happens once, at the payment-scoped APPROVE, so a key is spent even if later frames revert.
- S, checked, new: TXPARAM 0x0D legacy nonce, 0x0E nonce key count, 0x0F nonce keys hash, 0x10 nonce key 0. TXPARAM(0x01) returns nonce_seq.
- S, checked, new: "Single-use-key applications, such as nullifiers, MUST authenticate at least (sender, nonce_keys_hash, nonce_seq == MAX_NONCE_SEQ) in VERIFY and SHOULD bind the canonical signature hash via TXPARAM(0x08)."
- U: Magicians comments on key collisions across wallets (forum blocked in the build workspace). The EIP text itself says derived keys should be domain-separated. Since slots are keyed by sender, keys only need to be unique within one account.

## Post-quantum prior art

## Devnet implementation differs from the EIP text (read 24 Oct 2026)
Source: github.com/forshtat/ethrex branch `eip8141-tracer` at 9aa3645 (2026-10-01), `crates/common/types/transaction.rs` and `crates/vm/levm/src/opcode_handlers/frame_tx.rs`; sidecar `packages/types/src/contracts/FrameTx.ts` and `packages/executor/src/services/FrameTxService/codec.ts` at fcb4885. The devnet runs this code, so the signer must follow it where it differs. Re-check before relying on a public devnet; the branch moves.
- S: payload is `[chain_id, nonce_keys, nonce_seq, sender, frames, signatures, [max_priority_fee_per_gas, max_fee_per_gas, max_fee_per_blob_gas], blob_versioned_hashes, recent_root_references]`. The EIP text has `fees = [max_fee, max_priority_fee_per_gas]` and no recent roots in this list.
- S: `compute_sig_hash` replaces the elided signature bytes with **empty bytes**, not with their length as the EIP text says.
- S: `nonce_seq == 2^64 - 1` is statically invalid (no single-use marker). The sidecar caps `nonceSeq` at 2^64 - 2. Legacy nonce is `nonce_keys = [0]`, not `[]`.
- S: NONCE_MANAGER is `0x0000000000000000000000000000000000008250` (EIP text: 0x8250968C...). Slot formula is the same: keccak256(pad32(sender) || be32(key)).
- S: TXPARAM 0x0E nonce key count, 0x0F nonce keys hash, 0x10 nonce key 0, as in EIP-8250. TXPARAM 0x12 (resolved payer) is an ethrex extension.
- S: `max_verify_gas` is a node option (default 100,000). A code comment says one devnet "already runs a raised max_verify_gas for EIP-8272 proof benchmarking". Which value a given public devnet uses is unknown (Q3).

## Alt-mempool sidecar applies the 100,000 cap too (read 24 Oct 2026)
- S: forshtat/mempool-workshop-sidecar @fcb4885, `packages/executor/src/services/UserOpValidation/utils/validationPrefix.ts`: `MAX_VERIFY_GAS = BigInt(100_000)` is a constant, and `validateStructuralRules` refuses any transaction whose validation-prefix execution limits plus signature-verification cost exceed it (explorer rule "structure", citing ERC-7562 rule FRA-040). The check does not depend on staking or reputation. So, at this commit, the alt-mempool sidecar would refuse a Profile B transaction for the same reason as the public mempool. On the 16 Nov 2026 local runs those VERIFY frames are 690,937 to 812,757 gas. The alternative mempool is described as the path for validation above 100,000 gas. Ask the implementers whether a public devnet runs a different sidecar build or setting (OPEN_QUESTIONS Q3).

## Measured on a local ethrex eip8141-tracer (9aa3645) with the sidecar (fcb4885), re-run 16 Nov 2026
These are LOCAL measurements (scripts in this repository, raw responses in results/local/), not public-devnet results. They show how this client build behaves; the devnets may run other builds.
- Signature bytes do not count toward MAX_VERIFY_GAS: a Profile A transaction with an extra unused 30,000-byte ARBITRARY entry was accepted by the sidecar (`probe-bigsig.json`). Settles OPEN_QUESTIONS Q1 for this build.
- A keyed nonce costs 20,000 execution gas in the VERIFY frame that approves payment: the same one-line account uses 107 gas with the legacy nonce and 20,107 with a keyed nonce (`probe-control*.json`). This is a fifth of the public validation budget.
- A spent leaf cannot be used again: after inclusion the key's sequence moves from 0 to 1 (or the account nonce from n to n+1), and a second transaction for the same leaf is refused by ethrex and the sidecar ("Nonce mismatch"); with the next sequence the account's VERIFY reverts (`inclusion-*.json`). Settles Q4 for this build.
- EIP-8037 state gas on this build: 1,530 per state byte; a new account costs 120 bytes = 183,600; deploying code costs code bytes x 1,530. Deploying the 1,190-byte Profile A account inside the frame needs about 1,920,000 state gas, nearly four times MAX_VERIFY_STATE_GAS 500,000 (`deploy_state.json`, re-measured 16 Nov 2026). So `deploy + self_verify` is not possible for this account in the public mempool (Q7); deploy it in an earlier transaction.
- The node's own mempool (`--mempool.max-verify-gas`) refuses Profile B at 100,000 and includes it at 1,000,000 (`node-xmss-default-budget.json`, `inclusion-xmss-raised-node-budget.json`).
- The node only produces Hegota blocks through `engine_forkchoiceUpdatedV5` / `engine_getPayloadV6` / `engine_newPayloadV6` and with `--syncmode full`; its dev block producer uses V4 and fails (scripts/local_blocks.py stands in for a consensus client).
